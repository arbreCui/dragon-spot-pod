结论与范围
冻结的 SPOR64_BOOT64 / SPOBOOT64 仅覆盖 MCCG TYPE-K 原生终态 flux 的封存、读取和 clone。不能把 IMPORT clone 作为 GLOBAL64 到平面的投影，也不能把 ROOT-REF64 自复制作为独立 producer/终态求解证明。完整接线必须包含真实 REAL64 初态、原生 kernel、global canonical state、三平面投影、冻结 fission source、BOOT ingress 和 bootstrap commit。GLOBAL64 / ROOT-QFISS64 的旧 Source 已丢失，本文件的完整布局是明确的新合同建议，不声称旧 ABI 同字节恢复。

实施单元A：原生driver / host
在新的独立integration_source命名空间复制可用AXMAT driver与src/FLUDRV.f、src/FLU2DR64.f，不改冻结两文件。为初态加显式cold/warm typed入口及完整nunk×370 REAL64 staging；warm全项先验后才调用kernel。建议以已核验的typed initial_flux64参数传入driver，使调用者来源清楚，driver内部不再自行读GAR32。cold由同一真实调用者按已声明数学规则建立该数组，输入规则记录在Source和协议中。
MCCG producer保持原DOOR64、rebalance、acceleration、原material、370群、32 fission slots、8reg/14unknown/8mix、strict三残差和inner_state=1/it>=2。在strict branch只捕获真实terminal_flux、AKEFF、[EEXT,EUNK_LAST,EINR_LAST]、[IT,ITERF_LAST,IINR_STATE]，cap分支不得给有效终态；输出参数随真实成功返回。FLUDRV完成STATE/EPS/links之后，拥有完整MICROLIB2、TRACK、SYSTEM、RCONTRACT及独立plane/epoch binding的实际outer caller调用冻结PUBLISH_NATIVE，再保存XSM。若使用共享暂存而非显式输出参数，须在每次call reset并保证一对一调用，不能读取旧terminal残留。
轴向SPOT global生产同样必须从typed64初态入FLU2DR64；首次k初估及实际TYPE2分支可复用真实AXMAT_FLUKEF64更新式，其完整可用Source在validation/artifacts/axial-material-r64-snapshot-A-20261003/build/AXMAT_FLUKEF64.f。TYPE3保留B1HOM64原公式与原B1 SIGS/VOID等边界。不要把MCCG-only snapshot driver直接用于SPOT geometry。
真实终态值及strict分支调用是producer证明；封存副本、STATE文字及重读逐位相等仅是一致性检查。外部host必须固定新producer Source/编译链接命令/实际运行输入/日志与输出full-file SHA/7ID，且分别核验存储篡改。文件pin不足以在裸内存对象上证明终态真实求解。

实施单元B：SPOSTATE64 / GLOBAL64 / 三平面projection
从src/SPOSTATE.f90复制新SPOSTATE64：FLUX64/SPOT-KEFF64必须存在且type正确，FLUX/K-EFFECTIVE仅exactdemote镜像；norm、volume average、Gram rhs、solution、offspace、signed leakage全部由unknown64真实值计算。保留全局一次NUFISS-UNIT归一化、原面积/体积、MAT1D、完整FIXB Gram solve、basis排列及原rank门，禁止局部fit、clip或换rank。已有basis系数是原type2静态输入，可在乘法时精确提升；这不等于把迭代场从type2提升。
GLOBAL64建议为一个新独立root目录，不复制三份完整AX，含NPLANE=3、EPOCH=0、ROLE=原生global终态、真实strict terminal信息、CASE/RCONTRACT、KEFF64/RHO64(精确1/keff)、NORM64、完整AX TRACK/SYSTEM/MACROLIB3固定上下文、FLUX列表370×nunkAX(type4，包括全scalar/current unknown)、canonical DIMS/RANK/OFF/BOFF/GOFF、A(ncoef,type4)、GRAM、L(3×370,type4)、H(3,type4)、原basis与全部布局。ncoef按原偏移核验；只有全群rank2满足时才有ncoef=2220，不得用强制shape掩盖17群失败。
GLOBAL64也须绑定原完整径向三平面archive的TRACK/MICROLIB2/SYSTEM及A/B/A或AAA选择，避免全局算子与平面材料拼接。完整材料physical tree不裁剪，包含三个散射矩、全部8×32×370 NUSIGF/CHI/原能窗等；新current pin不自证旧失效资格。
新SPOPROJ64/BOOT projection读取同一GLOBAL64 canonical state；按原area/volume/MAT1D/FIXB公式在REAL64重构每平面scalar。生成新archive三项，不改输入：每项ROOT-FLUX64为type10长度370，每组type4长度该plane TRACK的nunk（当前14），KEYFLX顺序精确一致；scalar为新canonical projection，其余surface/current初值从已认证native64 seed原值完整保留，严格按原projection行为，不随意置零。FLUX type2只能是demote镜像。ROLE明确PROJECTED-BOOT，不可标NATIVE-K64或调用冻结PUBLISH_NATIVE冒称该投影再次通过MCCG终态。
三平面共用同一个global keff/rho/norm/epoch，plane标签1/2/3固定；plane维度、material、volume64、weight64、track和route均与其真实archive item一致。GLOBAL64有严格最后commit与外部fullpin；缺失global、错误scope/epoch/dims应普通拒绝。不能把新record添加进冻结21项ROOT64-SEAL inventory而仍声称原版本合同不变；用新bootstrap边界明确新版本精确inventory。
可复用B2H_RECONSTRUCT的REAL64 basis×coordinate算子及B2J完整布局/几何检查。不可直接调B2H_PROJECT做epoch0：它要求SOLVED/e seed并输出e+1。不可将未经径向求解的bootstrap seed贴SOLVED以满足此条件。

实施单元C：真实ROOT-QFISS64 / BOOT ingress / e0 commit
从同一个新projected-bootstrap archive构造所有三对MACRO0/FSOURCE，并在owning host内保持private/live直到BOOT完成。复用SPOR64_B2N.f90:414-449确定的真实标量loop和原material：fis64=sum_h REAL64(NUSIGF(im,ifis,h))*phi64(key,h)，q64(key,g)+=REAL64(CHI(im,ifis,g))*fis64*rho64，ifis=1..32、h/g=1..370。q64其余unknown为0、非负有限；qint64用原volume64积分。无FMA/reassociation假设、无额外normalization、clip或live fission。
ROOT-QFISS64明确是FSOURCE中type10长度370，每组type4长度nunk（当前14）；RHO、PLANE、STATE=FROZEN-QFIS、EPOCH=0及来源GLOBAL64完整绑定。DSOUR/type2、SPOT-QINT/type2、SPOT-KEFF/type2为exactdemote mirror。MACRO0由同一plane原MACROLIB全树复制，仅将所有NUSIGF置+0，防TYPE-S双计fission；其他材料record不变，源的真material parent仍保存原MICROLIB2，不用零NUSIGF MACRO0代替物理来源。
B2N公共CONT contract要求PROJECTED/e且e>0，不能放宽它至>=0。新bootstrap-specific reader/preflight使用上述新record与e=0；可抽取/复制同一原QFISS算子，显式不同入口，不冒称调用未改B2N已支持BOOT。
新的B2B BOOT typed分支保留原七physical objects+RCONTRACT、原TYPE-S0、INIT ON、REBA、caps/EPS/ACCE/merge、真实TRACK_f、全部物理/geometry/system验证；只用已完整准入ROOT-FLUX64与ROOT-QFISS64建立initial_flux64/fixed_source64，拒绝missing/type2/错epoch/dims/global/material/route。禁止旧FLUX/DSOUR fallback，仍调用实际FLU2DR64_CORE/DOORFV64与原strict terminal predicate。Frozen候选SPOBOOT64七参仅import，不能替代此真实BOOTrun；保留它作为native64 checkpoint admission helper。
BOOT source、seed和fresh SYSTEM均须证明来自同一GLOBAL64/plane/e0。系统由同一拥有者实际ASM产生，并在真正SOLVE前绑定；不能直接换用旧SYSTEM标签。旧BOOT若缺LEAK1D64会在ASM时把leakage预减到REAL32自散射；应与CONT一致使用真实LEAK1D64和未减system(SPOT-L1-RAW / SPOT-S0-PHYS)，由core在REAL64减泄漏，避免bootstrap遗漏该连续精度环。
成功BOOT仍由B2C既有严格发布建立SPOT-R64的FLUX/SOUR(type4)，不提前写SOLVED/0。三平面成功后，组装无archive生命周期marker的原bootstrap候选（TRACK/MICROLIB2/SYSTEM/FLUX三个list、SPOT-ITER-K精确global keff）；丢弃仅供e0输入的ROOT64包装或保存为分离证据，不能污染B2I exact inventory。
随后实际调用SPOR64_B2I_SEAL_BOOTSTRAP(AX_OUT,ARCH_OUT,AX,AX_TRACK,ARCH,RCONTRACT,status)，其既有检查/输出不变，形成CLOSED/0。这是真实完成三次径向BOOTrun之后的commit，不是启动前的自贴标签。其后原B2J从CLOSED/0投影到PROJECTED/1，B2K实际ASM绑定、B2N真实source、B2O/B2B CONT、B2R collect、B2W close继续原链。
