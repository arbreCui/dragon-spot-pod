# Phase-A9b B2v: one bounded real continuation return

B2v asks one deliberately narrow question: can the frozen three-plane
REAL64 radial continuation path return once from the existing PROJECTED/1
state under its already qualified inner termination rules?

It is not an outer Picard iteration.  It performs no returned axial solve,
no eigenvalue update, no leakage feedback, and no `CLOSED/1` commit.

## Frozen result

The one authorized activation returned successfully.  The private Dragon ran
for 16.332 s and executed three real ASM calls followed by three production
REAL64 CONT internal acceptance-and-publication paths.  Automatic retries
were zero.

The independent posterior ran twice with identical reports.  It checked
15,540 values each for REAL64 FLUX, SOUR, and independently recomputed QFISS,
plus their 15,540-value REAL32 mirrors.  The returned evidence was:

```text
RETURNED SHA-256 dd41a37d484b85612a495ff7b1f2233a53fbae1b462d89bd84db2a8809cef054
RETURNED bytes   231572260
cutoff by plane  59 138 126
```

The exact 36-line harness result transcript is frozen in `runtime_result.txt`
with SHA-256
`ace0bdcf25837c92e26ffd00bd71927ae4294633e71a3822bbc4ad7e32d7c57e`.
It is the bounded harness summary, not the raw Dragon log.  No second real
activation was made.

The result classification is
`ONE-REAL-THREE-PLANE-CONTINUATION-RETURNED`.  Its strongest scientific
meaning is that the production radial CONT internal acceptance and
publication path returned all three planes under the frozen code path.  It
does not upgrade the unexecuted outer/Picard, residual, or accuracy claims.

## One enabled route

The default-off wrapper selects `SpotStepR64` exactly once:

```text
PROJECTED/1
  -> ASM LK1D 1
  -> ASM LK1D 2
  -> ASM LK1D 3
  -> observer SPOR64T
  -> production B2T
  -> production B2S
  -> production B2B CONT (planes 1,2,3)
  -> production A9 REAL64 core
  -> production B2R
  -> RETURNED/1
```

`b2v_spor64t_observer.f90` is a validation-only replacement for the thin
production adapter.  A static normalized comparison requires it to be
identical to `src/SPOR64_B2U.f90` except for one unconditional formatted
write after B2T returns and before status dispatch.  That write exposes the
three ordered `INT64` ACA cutoff observations.  It does not branch, sum,
compare, feed back, or write them to an LCM/XSM object.

Consequently, a successful B2v run may claim execution of production ASM,
B2T, B2S, B2B, A9, and B2R.  It must also report
`PRODUCTION-SPOR64T-EXECUTIONS=0` and
`VALIDATION-OBSERVER-SPOR64T-EXECUTIONS=1`; it is not an end-to-end runtime
test of the frozen production adapter binary.

## Frozen numerical rule

No numerical control is introduced here.  Each plane returns only when the
production A9 core satisfies its existing strict rule

```text
e_ext < eps_out
e_unk < eps_unk
e_inr < eps_inr
inner state = STRICT
outer visit >= 2
```

with frozen tolerance bits `0x348637bd`, `MAXOUT=500`, and `MAXINR=740`.
There is no relaxation coefficient, damping, clipping, fitted correction,
restart, fallback to REAL32, retuning, or automatic retry.

The “outer visit” in this Boolean is an internal outer loop of one radial
fixed-source solve.  It is not a 2D/1D outer Picard map.

For this inherited type-S path, A9 assigns `e_ext=0`; it is not an
independently computed exterior residual.  The inherited `10*eps` near branch
can only schedule another outer visit and can never accept a plane.  B2v adds
or retunes no empirical control, but it does not claim that the inherited
solver contains no fixed numerical settings.

Accordingly, the frozen posterior line `EMPIRICAL-CONTROLS=0` means
“empirical controls added by B2v = 0”; it is not a claim that the inherited
solver contains no numerical cutoff.  In particular, the inherited ACA
`1e-7` predicate remains present and is only observed here.

The deterministic B2l materializer must reproduce a private PROJECTED XSM:

The radial sequential file is a private read-only copy of:

```text
SHA-256 f7b27cb4a5d37f903b93e49610e2daa2290d55c164e2ca0e73ccb8d22fe486b8

```

Both are hashed before and after Dragon and after the posterior checks.
These hashes prove that the tested bytes did not change.  They do not prove
that the archived TRACK objects and the sequential file were historically
generated by one tracking transaction.

The executed private Dragon SHA-256 is preserved in the manifest and harness
result transcript.  The compiler embeds its temporary source path in the
Mach-O image, so a later default-off rebuild checks the frozen inputs,
compilation, link symbols, and route structure but is not required to reproduce
that whole-file hash.  Byte-for-byte build reproducibility remains explicitly
not evaluated.

The sole Dragon process has hard safety caps of 60 s wall time, 55 s CPU,
2 GiB leader RSS, 512 MiB per file, and 64 MiB log, with one thread and core
dumps disabled.  It runs in a fresh process group.  On timeout or a resource
failure only that group is terminated, and there is no retry.  The limits are
execution safety bounds, not physical or convergence criteria.

## Independent returned-state evidence

After a normal return, `check_b2v_real_returned.f90` opens PROJECTED and
RETURNED read-only and links only GANLIB/UTILIB.  It does not link B2N, B2R,
Dragon, ASM, FLU, SPOMOC, or transport routines.  It is run twice and its
reports must be identical.

The checker verifies:

- exact PROJECTED/1 and RETURNED/1 root schemas and lifecycle states;
- three index-owned SOLVED/1 children and exact RHO, epoch, K, KEYFLX, and
  leakage bindings;
- finite, REAL32-range-safe REAL64 FLUX/SOUR/QFISS payloads and bit-exact
  REAL64-to-REAL32 compatibility projections;
- recursive bit identity of same-index TRACK and MICROLIB2 copies;
- three SYSTEM authorities, response inventories, and the frozen B2m
  TX/S0 physical/used binary32 formula;
- all 15,540 QFISS values by independently repeating the frozen B2N scalar
  loop order from the PROJECTED flux and microscopic fission data.

Normal process exit or a completion marker alone is never sufficient.

## Classification

- PROJECTED preparation or the sole Dragon activation hitting a timeout,
  managed signal, or resource cap:
  `INVALID-NO-SCIENTIFIC-RESULT`;
- nonzero or abnormal Dragon end, including an internal failure signal:
  `FAILED-NO-RETURN`;
- normal process exit with a missing or inconsistent route/log census:
  `INVALID-RUNTIME-EVIDENCE`;
- normal return with missing/rejected XSM evidence, including a posterior
  timeout or resource failure:
  `INVALID-RETURNED-EVIDENCE`;
- every runtime and independent posterior condition satisfied:
  `ONE-REAL-THREE-PLANE-CONTINUATION-RETURNED`.

`FAILED-NO-RETURN` does not prove physical divergence, absence of a fixed
point, or failure of the 2D/1D method.  Several internal failures are
deliberately compressed by the host boundary, and frozen MAXOUT exhaustion is
only a nonaccepted return.

Each plane value is already an accumulated local-predicate-difference count
along that plane's live trajectory.  The observer preserves the three plane
values separately, performs no cross-plane aggregation, and never uses them
for acceptance.  Any positive value adds only
`INHERITED-ACA-CUTOFF-LOCAL-PREDICATE-DIFFERENCE-OBSERVED`.  The count is
not the number of guard evaluations and is not a zero-cutoff rerun; it cannot
establish sensitivity of the solution or of convergence.  Three zeros mean only
`NO-REACHED-LOCAL-PREDICATE-DIFFERENCE-OBSERVED`; they do not prove that the
inherited cutoff has no effect.

The independent posterior does not recompute the A9 transport equation,
termination norms, or a residual.  Therefore the frozen-inner-rule statement
is code-path provenance: production CONT reached its internal acceptance and
publication path for all three planes.  It is not an independent numerical
convergence or residual validation.

Even a successful B2v run does not establish outer 2D/1D Picard convergence,
an eigenvalue or power solution, an independent residual bound, SPOD rank
accuracy, mesh/angle/energy convergence, agreement with another transport
code, or reproducibility from repeated runs.
