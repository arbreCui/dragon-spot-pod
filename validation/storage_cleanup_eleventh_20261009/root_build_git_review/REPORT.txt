Git可安全压缩的边界（仅建议，本轮未执行）
保留所有可达与未引用对象的repack可以把loose对象和旧packs重新组织，不更改分支历史。例如以后另获授权并暂停并发Git写入时，可评估git repack -a -d --keep-unreachable --threads=1；Git官方文档说明--keep-unreachable保留现有pack中的未引用对象，也打包未引用loose对象。先保存refs/reflogs/所有9409对象及lost-found基线，后验每个对象仍可读、refs/分支/tag/本地capture和lost-found不变。不要删除refs/codex、分支、tag、reflog、worktrees、lost-found，不手工删objects/pack。不能换成普通gc/prune、prune=now、reflog expire或历史改写；官方gc会涉及未引用对象与reflog等清理。实际收益未知，压缩期间临时占用可能增长，不给释放承诺。
依据：https://git-scm.com/docs/git-repack （--keep-unreachable）；https://git-scm.com/docs/git-gc （默认清理/expiry范围）。这些建议不执行任何命令。
